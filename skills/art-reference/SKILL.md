# 艺术参考检索

> **默认积极**：本模式是艺术创作模式。**创作前先找参考**，而不是凭记忆直接写提示词。
> 但"积极"不等于"每次都搜"——判据是**这个决定有没有客观依据可查**（见 §1）。

---

## 0. 传统艺术优先（这是本手册的立场）

> **风格会过时，根基不会。** 传统艺术的具体画风可以更新，但**审美、建筑、人物**是一脉相承的：
> 一个 2026 年的日式动画角色，其**头身比、面部结构、衣纹走向、场景透视、光影逻辑**，
> 全部建立在文艺复兴以来的造型传统与更早的东方绘画传统之上。潮流只是**表面处理**。

**实践含义**：

| 你要解决的 | 该去哪里找根基 |
|---|---|
| 人物动态 / 解剖 / 手部结构 | 古典雕塑与人体素描（**不是**上周的热门插画） |
| 建筑 / 场景 / 城市透视 | 建筑档案、古典绘画中的建筑、地图集 |
| 衣纹 / 褶皱 / 服饰结构 | 博物馆服饰藏品、古典绘画的布料处理 |
| 光影 / 明暗 / 体积感 | 伦勃朗以降的油画、学院派素描 |
| 构图 / 视觉引导 | 宗教画与历史画的经典构图 |
| 东方传统（水墨、工笔、屏风构图） | 中国古画高清库与古籍扫描 |

**所以顺序是**：先确立**结构与造型**的参考（传统艺术），再定**风格表皮**（当代插画）。
反过来做——先追风格再补结构——是画面"飘""软""站不住"的最常见根因。

## 1. 什么时候必须去找参考

| 情况 | 找什么 |
|---|---|
| 要写风格 / 画风描述（"日式厚涂""赛璐璐"） | 找**同类作品的视觉特征词**，而不是拍脑袋写形容词 |
| 要定构图 / 景别 / 运镜 | 找**同类型镜头的画面**（Sakugabooru 是分镜/作画金矿） |
| 要设计角色（服装、发型、特征细节） | 找**服装史 / 民族服饰 / 角色设计参考**，避免发明不合逻辑的东西 |
| 要画某个具体姿势 | 找**姿势参考**，别凭空猜解剖 |
| 要定配色 | 找**配色方案**或从参考图提取色板 |
| 要材质 / 环境（金属、布料、地形、光照） | 找 **CC0 材质与 HDRI**（Poly Haven） |
| 提示词写不出想要的词 | 查 **booru 受控词表**（§5，最值钱的一招） |
| 简单改色、已有明确参考图 | **不用搜**，直接做 |

> 判据：**这个决定有客观依据可查吗？** 有就查。没有就别为了"显得勤奋"浪费一轮。

## 2. ⚡ 第一步永远是跑探针（可达性随时在变）

**别背站点清单**——本机**代理开关会变**，可达性跟着变。先跑：

```powershell
$S = "<本 skill 所在目录>/scripts"
& "$S/check-sites.ps1"              # 全部，约 15 秒，并发探测
& "$S/check-sites.ps1" -Group 传统   # 只测传统艺术类
& "$S/check-sites.ps1" -Json        # 机器可读
```

它输出：**代理当前状态**（读注册表 `Internet Settings`）+ 分组可达性 + `可达 N/M`。
判定分三档：`✅ 通` / `⚠️ 可达但挡爬虫（403/405/429）` / `❌ 网络不可达`。
**⚠️ 这一档必须分清**：`⚠️` 说明站点其实活着，只是拒绝爬虫——换成 `web_fetch` 或走搜索工具很可能能拿到内容。

### 代理开关怎么应对

本机的代理**已配置但默认关闭**（`ProxyServer = 127.0.0.1:7890`，`ProxyEnable = 0`）。
**用户会在需要时手动启用。** 所以：

| 代理状态 | 你的做法 |
|---|---|
| **关闭**（默认） | 只用当前可达的站点；外网内容走 §4 的镜像替代 |
| **已启用** | 🔁 **重跑一次 `check-sites.ps1`** —— 会出现一批新可达的站点（Pixiv / ArtStation / Wikimedia / Civitai 等），此时优先用**源站** |
| 不确定 | 跑探针，它会告诉你 |

> ⚠️ **不要自己改系统代理设置**。那是用户的网络配置，不是你的。你只负责**探测**和**据此选站点**。
> ⚠️ 若用户说"我开代理了"但探针显示仍不可达，可能是代理只对浏览器生效、未设 `HTTP_PROXY` 环境变量——
> **把观察如实告诉用户**，别硬试。

## 4.5 取图的完整流程（**预设站点只是起点，不是边界**）

要什么就去搜什么。**不要把下面的站点清单当成穷举** —— 它只是"已知能通"的起点。

### 三级取图策略（按顺序走）

**① 多引擎搜图 —— 直接搜画面**

| 手段 | 怎么用 |
|---|---|
| `web_search` / `multi_search` | 搜「角色名 + reference」「姿势 参考」「<作品名> 設定画」等；要交叉验证用 `multi_search` |
| **图片搜索直达** | `image.baidu.com`、`cn.bing.com/images` —— **想不出词时直接搜画面，比文字检索高效得多** |
| `platform_search` | Bilibili / YouTube（作画、运镜参考）、GitHub（工作流、节点） |
| `web_fetch` | 已知确切 URL 时直接取（API 端点见 §3 / §4） |

**② 被屏蔽时的兜底：用 computer use 模仿真实用户**

很多站点**拒绝爬虫但允许浏览器**（Pixiv / ArtStation / 需登录的站 / 强 Cloudflare 的站）。
本机装了 `dsh-computer-use-win`，工具是 **`mcp__wincu__*`**：

```
windows_computer_use_list_windows / activate_window   打开并聚焦浏览器
windows_computer_use_type_text                       在搜索框输入关键词
windows_computer_use_snapshot / ocr                  看结果（截图 + UI 树 / OCR）
windows_computer_use_click / scroll                  像真人一样点击、翻页
```

> ⚠️ **这是兜底手段，不是首选**：它慢、吃 token，只在 HTTP 路径**确实不通**时才用。
> ⚠️ **不要用它做违反站点条款的事**（绕登录墙、批量抓取、绕付费墙）。
> 它只是"用浏览器看"，**不是爬虫**。
> ⚠️ 用完**把观察如实写进报告**：说明这张图是"通过浏览器人工路径获取的"。

**③ 🔴 AI 评估后才选 —— 拉到的第一张不一定能用**

**下载或截图后，必须用 `read_image` 实际看图再决定**：

| 评估项 | 要求 | 不合格的后果 |
|---|---|---|
| **主体对不对** | 是要的那个角色 / 物体，不是同名不同人 | 生成出完全错的东西 |
| **清晰度** | 能看清五官与结构 | 糊图**直接拖垮**生成质量 |
| **角度** | 做角色参考时：正脸 > 侧脸 > 全身小图 | 侧脸参考出不了正脸 |
| **无水印 / 无遮挡** | 水印会**渗进生成结果** | 成品带别人水印 |
| **是否 AI 生成** | 有些"参考图"本身就是 AI 画的 | 会把它自己的缺陷一起学过来 |
| **版权可用性** | 见 §7 | 交付物出问题 |

**不合格就换下一张，不要将就** —— **参考图质量决定生成质量的上限**，
而"凑合用的参考"比"没有参考"更糟：它会**稳定地**把你带偏。

### 下载模型 / 工作流时的镜像

**HF 官方站从本机不可达**（实测超时）。要下模型或工作流，走镜像：

| 站点 | 实测 | 用法 |
|---|---|---|
| ❌ `huggingface.co` | **超时不可达** | 不要直接试 |
| ✅ **`hf-mirror.com`** | **200 可达** | 把 HF 的 URL **域名替换**即可：`huggingface.co/<repo>` → `hf-mirror.com/<repo>` |
| ✅ **`modelscope.cn`**（魔搭） | **200 可达** | 国内模型库，很多热门模型有镜像仓 |
| ❌ `github.com` | **超时不可达** | 需要 GitHub 上的工作流/节点时，走镜像或让用户开代理 |

```powershell
# 例：HF 的模型 → 换成镜像域名再交给 download_model
# https://huggingface.co/<owner>/<repo>/resolve/main/<file>
# → https://hf-mirror.com/<owner>/<repo>/resolve/main/<file>
mcp__comfymcp__download_model  url=<替换域名后的 URL>  relative_path=models/<类别>
```

> ⚠️ **下载前先问用户** —— 多 GB 的下载要走用户的带宽与磁盘。
> ⚠️ 下载**可能很慢**，用 `wait=false` 拿 `download_id` 再轮询，别阻塞在一处。
> ⚠️ 镜像站**不保证与官方完全同步**；下完核对文件大小，必要时比对 hash。

## 5. 检索工具与两个陷阱

### 工具怎么选

| 工具 | 什么时候用 |
|---|---|
| `web_search` | 常规检索，快 |
| `multi_search` | **跨引擎交叉验证**（要"多个来源都这么说"时） |
| `advanced_search` | 要**限定时间**或指定引擎 |
| `platform_search` | 专搜 GitHub / V2EX / Bilibili / Reddit / HN / StackOverflow / npm |
| `web_fetch` | **已知确切 URL** 时直接取（如上面的 API 端点） |

> 这些搜索工具由第三方插件（`dsh-free-search`）提供，**挂在宿主层、与预设无关，一直在**。

### 陷阱一：别把列表页拉进上下文

实测教训：`web_fetch` 一个 booru 的**帖子列表页**，会塞进**几万字符**缩略图标记，然后被截断——
**真正有用的信息反而看不全**。

- ❌ 不拉 `?page=post&s=list&tags=...` 这类帖子列表
- ✅ 能用 **JSON API 加 `limit`** 就别用 HTML 页面
- ✅ 要单张图就找具体 `post/view&id=<数字>` 页面

### 陷阱二：booru tag 词表是金矿，但不能直接抄

booru 的 tag 是**人工维护的受控词表 + 使用量排序**（如 `blue_hair` 67 万、`twintails` 5.3 万）。
这是"把模糊中文感受翻译成精确描述"的最短路径。

> ⚠️ **但它是检索用的描述体系，不是 Qwen 2.1 / H3 的 prompt 语法。**
> 正确姿势：**用 tag 校准你的观察维度，再用目标模型的语言写提示词**。
> （`masterpiece`/`best quality` 那类咒语对这两个模型无效，见 `comfyui-prompt-craft`。）

## 6. 落盘与出处（参考也是资产）

按 `comfyui-project-layout` 的规范落盘：

```
projects/<项目>/
├─ 00_dev/reference/          ★ 项目级参考（风格板、材质、配色、考据图）
│   ├─ <名称>.png
│   └─ <名称>.meta.json       ← 必记 source（站点 + URL + 作者/馆藏号）
└─ 30_shots/<seq>/<shot>/10_ref/   ★ 镜头级参考
```

- **下载的参考图** → `00_dev/reference/`（项目级）或 `10_ref/`（镜头级）
- **必须记出处**：站点 + URL +（若有）作者/馆藏号 → 写进 `.meta.json` 的 `source` 字段
  （参考图**不写** seed/params，它不是生成物；但 **`source` 必填**）
- **纯文字结论**（如"这种打光业界叫 X"）→ 写进项目笔记或 `60_review/`，**附来源链接**
- **覆盖已有参考图前先跑 `safe-write.ps1`**（见 `comfyui-project-layout`）

## 7. 版权红线（**免费 ≠ 可商用**）

| 来源 | 能不能直接用 |
|---|---|
| **公共领域**（Met / Art Institute / 书格 / Europeana 中标注 PD 的） | ✅ 可商用、可改。**交付物素材的首选** |
| **CC0**（Poly Haven 等） | ✅ 可商用、免署名 |
| **署名类许可**（CC-BY 等） | ⚠️ 可用，但**必须按许可署名**，并把署名写进交付物 |
| **他人作品**（Pixiv / 花瓣 / Lofter / booru / 拍卖图录） | ❌ **只能当参考看**，不能直接进交付物，不能描图 |

**规则**：

1. 参考图是**给你看的**，交付物必须是**你自己生成的**。
2. 需要**直接使用**外部素材时，**只从公共领域 / CC0 拿**。
3. 用户要求"照着这张图画"时**照做**（那是用户的素材与责任），但**在报告里注明来源**。
4. 生成结果若明显带有某位在世作者的签名风格，**在交付时点出来**让用户判断。
5. **古画也有版权例外**：博物馆对**翻拍照片**可能主张权利（即使原作已过版权期）。
   商用前优先选明确标注 **Open Access / Public Domain** 的条目。

> 拿不准就**说出来**，别默默用。这条红线不因为"只是个参考"而放宽。
