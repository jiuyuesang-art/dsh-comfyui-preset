# 批量渲染（一次跑完 N 项）

## 什么时候用 / 什么时候别用

**用**：同一次任务要出 **≥2 项** —— N 个提示词变体、一组镜头、一组种子、图 + 视频混合。

**别用**（走 `comfyui-mcp-ops` 的单任务流程）：
- 只有 1 项
- 还没定下工作流 / 参数（先调通一张，再批量）
- 每张都要你看过才决定下一张长什么样

## 为什么（这是省 token 的关键）

逐张走「提交 → 等 → 唤醒 → 取图」：**N 项 = N 次唤醒 + N 轮上下文重建**。
批次走「一个脚本跑完」：**N 项 = 1 次唤醒**。

模型侧的动作只有三步，**不要在里面加第 4 次工具调用**：

```
① 写计划 JSON
② 干跑验证    batch-render.ps1 -PlanPath … -DryRun
③ 后台跑一次  run_in_background: batch-render.ps1 -PlanPath … [-OutDir …]
   → 然后结束本轮，什么都不做
   → 被唤醒时，读末行 +（需要细节再读）报告
```

## 🔴 三条硬约束

1. **不要逐项提交**。既然用了本脚本，就不要再对每一项调 `run_workflow` —— 那会变回 N 次唤醒，白做。
2. **等待机制不变**。每项仍由 `wait-job.ps1` 阻塞在 ComfyUI 的 WebSocket 上：事件驱动、**不设超时**。
   批次跑几十分钟（视频更久）是正常的，**不要中途去查、不要打断**。
3. **提交前必须干跑**。`-DryRun` 会提前暴露：节点地址写错、工作流路径不存在、名字重复。
   这些在提交后才发现，就是白等一轮。

## 计划文件

最小可用：

```json
{
  "workflow": "02_env/workflows/qwen21_t2i.json",
  "seedAddress": "7.seed",
  "seedBase": 1000,
  "seedStep": 1,
  "items": [
    { "name": "shot0010_a", "params": { "6.text": "……", "9.filename_prefix": "shot0010_a" } },
    { "name": "shot0010_b", "params": { "6.text": "……" } }
  ]
}
```

- `params` 的键是 **`"<节点id>.<输入名>"`**，值原样写进工作流 —— 不做任何猜测、不做变量替换。
- `seedBase`/`seedStep`：第 i 项的种子 = `seedBase + (i-1) * seedStep`，**只在 params 没自己写种子时生效**。
- 每项可单独覆盖 `workflow`（同一批混跑不同工作流）。
- 完整字段、多工作流、视频示例 → `references/plan-format.md`。

**节点 id 从哪来**：打开工作流 JSON（API 格式）里的数字键。MCP 的 `run_workflow` 用的也是同一份文件。

## 显存：每项之间要复位

12GB 卡上连续跑不同模型/分辨率，显存会越跑越窄，最后 OOM。本脚本在**每项之间**处理：

- **默认**：`POST /free`（`unload_models` + `free_memory`），然后等显存真的掉下来（默认最多 25s，`-FreeWaitSeconds`）。
  实测：`4.2 → 10.7 GB` 可用，下一项从干净状态加载。
- **更狠**（真的重启进程）：`-RestartCommand '<同步命令>'`，每项之间执行一次，再轮询 `/system_stats` 等它回来。
  **只在 `-free` 不够时用** —— 重启要几十秒，还会让下一项重新加载模型。命令怎么写取决于你的 ComfyUI 怎么装的（官方包 / comfy-cli / 便携版各不相同），**不要瞎猜，问用户**。
- `-NoFree`：关掉。只在显存本来就富余（≥24GB）且模型不变时考虑。

## 产物

- 不给 `-OutDir`：只记录文件名，产物仍在 ComfyUI 的 output 目录。
- 给 `-OutDir`：每项产物**下载**到该目录，文件名前缀项名（`shot0010_a__xxx.png`），不会互相覆盖。
- **不要再用 `fetch_outputs` 逐项搬运** —— 那正是本脚本替你省掉的往返。

## 结果怎么读

末行（机器可读，**先读它**）：

```
BATCH_DONE	ok=3	fail=0	total=412.3s	out=C:\…\30_key	report=C:\…\plan.result.json
```

`BATCH_DONE` 全成功 / `BATCH_PARTIAL` 有失败但跑完了 / `BATCH_FAILED` 全失败。
退出码同义：`0 / 1 / 2`；批次被中止（重启没回来）是 `3`。

进程里还会打印每项一行（`✅ name DONE 137.9s`），**但被唤醒后不需要重读日志** ——
需要逐项细节（prompt_id、参数留痕、错误文本、产物清单）时，读报告：

```json
{ "ok": 3, "failed": 0, "total": 3, "totalSeconds": 412.3,
  "items": [ { "name": "shot0010_a", "status": "DONE", "seconds": 137.9,
               "promptId": "…", "files": ["out_A_00001_.png"], "saved": ["C:\\…"], "error": null } ] }
```

## 失败怎么办

- **默认不中断**：某项失败 → 记下来 → 继续跑剩下的 → 最后 `BATCH_PARTIAL`。
  单项失败通常是个例（提示词被拒、某模型 OOM），不该毁掉整批。
- `-StopOnError`：任何一项失败就停（后面的项标记 `SKIPPED`）。**用于失败会连锁的场景**（例如共享同一个显存吃紧的模型）。
- **不要自动重跑失败项**。先读 `error` 字段判断：参数问题改参数、OOM 降分辨率或加 `-RestartCommand`，
  然后**只把失败项写进新计划**重跑。

## 常见坑

| 现象 | 原因 / 怎么办 |
|---|---|
| `BATCH_FAILED 计划解析失败：工作流里没有节点 99` | `params` 地址写错。干跑就能发现。 |
| `名字重复` | `items[].name` 必须唯一，否则产物前缀会撞。 |
| 提交就报「工作流校验失败」 | 工作流本身缺输入 / 模型文件名不对。先用单任务流程调通一张。 |
| 每项都很慢（比单张慢） | 正常：清显存后下一项要重新加载模型。批次赢的是**唤醒次数**，不是单张速度。 |
| 中途 OOM | 加 `-RestartCommand`，或降分辨率/步数后重跑该批。 |

## 与其它手册的边界

- 工作流怎么搭、参数怎么填、MCP 工具怎么用 → `comfyui-mcp-ops`

- 产物落在哪个目录、镜头码怎么起名 → `comfyui-project-layout`
- 出图后要不要质检、怎么质检 → `comfyui-review`
