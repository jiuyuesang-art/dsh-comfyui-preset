# 产物视觉质检规范

> **这不是可选项。** 本模式下任何产物在交给用户之前都必须过这一关。
> 交付流程：`生成 → 审查 → 落盘报告 → 交人 review →（按意见改）→ 再审`。

---

## 0. 四条红线

1. **不许自我批准。** 你可以给判定（PASS / NEEDS_WORK / FAIL），但**最终采纳权在人**。报告必须交人 review，不能自己说"通过，已交付"就完事。
2. **每条结论必须指向画面里看得见的证据。** 禁止「整体效果不错」「质量尚可」这种没有落点的评价。要写成「左手食指与中指粘连」「背景招牌第 3 个字缺了右边一竖」这个颗粒度。
3. **必须真看图。** 用 `read_image` 实际读产物。**禁止**根据 prompt、参数、或"模型通常表现"来推断质量。
4. **视频必须声明抽样限制。** 你是通过抽帧看的，不能声称看了每一帧；也听不到音频。报告里必须写明「本次审查基于 N 帧抽样，未逐帧检查，音频仅做技术规格核对」。

## 1. 审查流程（照做）

```
① 定基准 —— 这次要跟什么比？
     改图/换风格 → 比**输入参考图**（ComfyUI input 目录或 10_ref/）
     重出一版   → 比 **old/ 里的上一版**
     从零生成   → 比**提示词意图**（把 prompt 的每个要素列成清单逐条核对）

② 读产物
     图片 → read_image 直接读
     视频 → 先抽帧，再逐帧读（脚本见 §4）

③ 按 §2 或 §3 的清单逐项过，每项都写下「看到什么」

④ 定级（§5）

⑤ 生成前后对比图（脚本见 §4）

⑥ 落盘报告 → 30_shots/<seq>/<shot>/60_review/<seq>_<shot>-review-v<NNN>.md

⑦ present 给用户，明确说「等你 review」
```

## 2. 图像审查清单（严格）

> 每项给 `通过 / 有问题 / 不适用`，**有问题必须写清位置与现象**。

| # | 维度 | 具体查什么 |
|---|---|---|
| 1 | **主体保真**（改图最关键） | 身份特征是否保持：五官、发型、发色、瞳色、服装款式与配色、体型比例、标志性道具。**逐项比对基准图**，不要凭印象 |
| 2 | **提示词符合度** | 把 prompt 拆成要素清单，逐条在画面里找。**缺了哪个要素要点名**；多了没要求的要素也要说 |
| 3 | **解剖与结构** | 手指数量与关节、手臂与腿的连接、耳朵位置、眼睛对称、牙齿、脖子长度；建筑/道具的透视对齐 |
| 4 | **文字渲染** | 要求出现的字是否**正确、完整、无缺笔**；有没有多出无意义的鬼画符文字。有文字需求时这是重点项 |
| 5 | **技术瑕疵** | 明显接缝、涂抹/糊化区、重复纹理、边缘光晕、色带、噪点、压缩块、贴图接缝 |
| 6 | **构图** | 主体是否被裁切、主体位置与留白、视线方向是否留空间、有无意外入画的杂物 |
| 7 | **风格一致性** | 与项目风格板、以及**同一序列其他镜头**是否同一套画风/配色/打光 |
| 8 | **通道与格式**（如要求） | 要求透明底时，是否**真的**有 alpha、边缘是否干净、有无白边 |

## 3. 视频审查清单

**先跑 §4 的抽帧**，然后：

| # | 维度 | 具体查什么 |
|---|---|---|
| 1 | **逐帧质量** | 对抽出的每一帧套用 §2 的清单（可以简化，但主体保真与解剖不能省） |
| 2 | **时间一致性** | 相邻帧之间：脸有没有变、衣服花纹有没有跳、背景有没有漂移、道具是否变形 |
| 3 | **运动合理性** | 从帧序判断运动方向/幅度是否与意图一致；有没有该动的地方不动、或抖动 |
| 4 | **首尾帧** | 第一帧和最后一帧是否有黑帧、突变、半截动作 |
| 5 | **技术规格** | 用 ffprobe 的输出核对：时长、帧率、分辨率、编码是否符合交付要求 |
| 6 | **音频** | ⚠️ **你听不到音频**。只能核对 ffprobe 报的技术事实（有无音轨、编码、声道、采样率）。内容层面一律写「未审查（无法听）」 |

## 4. 两个脚本（都在本 skill 的 `scripts/` 下）

```powershell
# 取本 skill 目录后：
$S = "<本 skill 所在目录>/scripts"

# ① 视频抽帧 + 接触表（默认 9 帧，均匀取每段中点，避开首尾黑帧）
python "$S/review.py" frames <视频路径> <输出目录> --count 9 --cols 3 --sheet <接触表路径>
#   同时输出一行 META {json}：时长/分辨率/帧率/编码/音频轨/帧文件名 —— 直接抄进报告

# ② 前后对比图（并排 + 差异×4 增强）
python "$S/review.py" compare <前> <后> --out <输出路径> `
    --label-before "基准" --label-after "本次 v003" --title "010_0010 关键帧 前后对比" --mode both

# ③ 多图接触表（例如把各帧或各候选拼一张）
python "$S/review.py" sheet <图片或目录...> --out <输出路径> --cols 3 --title "候选对比"
```

> Python 需要 Pillow。优先用 PATH 上的 `python`；若不可用，用 `load_workspace_dependencies` 取捆绑 Python 的绝对路径。
> 脚本已强制 UTF-8 输出（不然 Windows 上中文会乱码）。
> `compare` 的 `--mode`：`side` 只并排 / `diff` 只差异 / `both` 三者都出（默认，推荐）。

## 5. 判定分级

| 判定 | 含义 | 下一步 |
|---|---|---|
| **PASS** | 无可见缺陷，可直接交付 | 交人确认 |
| **PASS_WITH_NOTES** | 可用，但有**已列明**的缺陷 | 交人确认是否接受 |
| **NEEDS_WORK** | 需重出；缺陷可修 | 给出**具体参数修改**（见 §6），重出后再审 |
| **FAIL** | 根本性不达标（主体跑了、严重解剖崩坏、文字全错） | 说明根因，换思路而不是微调 |

> **默认从严**：拿不准就降一级。宁可多审一轮，不要把有问题的东西当成品交出去。

## 6. 修改建议要写到"能直接照做"

❌ 「建议优化提示词」
✅ 「把 `steps` 从 8 提到 20；`cfg` 保持 1；在 prompt 末尾补 `keep the facial features unchanged`；参考图槽位 `<image2>` 换成更清晰的正脸照」

**按缺陷类型给对应手段**（本项目能调的都在这）：

| 缺陷 | 可调手段 |
|---|---|
| 主体漂移 / 换脸 | 强化保留话术、换更清晰的参考图、提高 `<imageN>` 引用权重、加 ControlNet |
| 细节糊 / 结构崩 | 提 `steps`（8→25）、换更高量化精度权重、降分辨率 |
| 提示词要素缺失 | 补进 prompt 的**具体位置**（不要笼统"描述更详细"） |
| 文字画错 | cfg 提到 2、把字加引号、缩短字数 |
| 风格不一致 | 统一风格板描述、固定 `seed` 基线、加风格 LoRA |
| 视频跳变 | 降分辨率/缩短时长、换蒸馏步数、检查参考帧是否足够 |
| 音画问题 | ⚠️ 听不到音频，只报 ffprobe 技术事实，交给人工判断 |
